# 🚗 FuelTracker（随记油耗）

一款注重简洁体验的 Android 车辆油耗与日常记账应用。

FuelTracker 基于 **Kotlin** 和 **Jetpack Compose** 开发，采用本地数据存储，支持多车辆管理、油耗计算、用车费用记录、停车辅助和数据备份等功能。

项目逐步引入 **Miuix** 组件库，尝试打造更贴近 MIUI / HyperOS 设计语言的界面体验。

## ✨ 核心功能

- **⛽ 油耗统计与分析**：以满箱法为基础，结合多条加油记录进行油耗计算，支持漏记记录处理、数据校验和异常数据识别，尽可能减少错误数据对统计结果的影响。
- **🔀 油耗算法切换**：提供不同的油耗计算方式，用户可以根据记录习惯和数据情况选择合适的算法。不同算法的统计结果可能存在差异。
- **🚙 多车辆管理**：支持添加、编辑、删除和切换车辆，分别管理不同车辆的加油记录、油耗数据与用车费用。
- **🧾 日常费用记录**：记录停车、保养、高速等车辆相关支出，方便统计和查看用车成本。
- **🅿️ 智慧停车**：记录停车位置、楼层和车位信息，通过首页卡片和通知辅助记忆停车地点，支持取车操作。
- **🔄 数据备份与迁移**：支持 JSON 数据导出与恢复，也支持导入“小熊油耗”导出的 CSV 历史记录，并进行数据去重与校验。
- **📊 数据统计**：支持按车辆、年份和月份查看加油记录、油耗趋势及费用情况。
- **🎨 个性化界面**：支持深色模式、背景设置、圆角布局和流畅动画；部分界面使用背景模糊与悬浮玻璃效果。

## 🧮 关于油耗计算

FuelTracker 的油耗统计并不是简单地将某一次加油量除以行驶里程。

应用以满箱法为基础，结合连续加油记录建立计算区间，并对漏记加油、非满箱记录和异常数据进行处理。

需要注意：

- 满箱记录是建立可靠计算区间的重要依据。
- 漏记记录可能影响部分区间的计算，需要结合前后记录判断。
- 异常里程、异常加油量等数据可能被识别或排除。
- 不同计算算法可能采用不同的数据处理方式，因此统计结果不一定完全相同。
- 记录越完整、里程和加油量越准确，统计结果通常越有参考价值。

油耗数据属于根据用户输入记录计算得出的估算结果，仅供个人用车记录和参考，不应作为车辆检测、维修或其他专业判断的唯一依据。

## 🚗 车辆数据库说明

项目内置车辆数据库：

`app/src/main/assets/car_brands.json`

其中包含车型名称、年款、油箱容量、能源类型及燃油标号等车辆资料。

相关数据来源于第三方公开资料，经过整理、筛选和清洗后用于车型查询。

## 🔒 隐私与数据处理

FuelTracker 采用本地优先的数据管理方式，尽量减少用户个人信息的收集和处理。

### 1. 数据存储

车辆信息、加油记录、油耗数据、费用记录、停车信息及应用设置等核心数据主要保存在用户设备本地。

应用不提供用户注册、账号登录或开发者自建云同步服务。

### 2. 位置信息

应用仅在停车辅助等相关功能中，根据用户授权使用 Android 设备的定位能力，以辅助获取当前位置和停车地点信息。

- 应用通过 Android GPS 定位接口获取当前位置，不主动使用网络定位方式获取坐标。GPS 卫星定位本身不需要互联网连接，但实际效果会受到卫星信号、设备环境和系统定位状态影响。
- 应用会优先尝试获取当前位置；主动定位未成功时，会尝试使用近期的 GPS 缓存位置。
- 获取坐标后，应用会调用 Android Geocoder 接口，尝试将经纬度转换为区县、街道或附近地点名称。地址解析可能使用网络服务，因此即使 GPS 已经成功获取坐标，离线时也可能无法解析出具体地址。
- 地址解析失败时，应用可能显示 GPS 经纬度，供用户确认或手动填写停车位置。
- 用户确认并保存停车记录后，停车地点文字会保存在设备本地数据库中。如果保存的是经纬度文字，该文字也会作为停车地点信息保存。
- 用户可以通过系统权限设置关闭定位权限，也可以始终手动填写停车位置。

应用不以持续后台追踪用户位置为目的，也不运营开发者自建的地址解析服务器。。

### 3. 通知信息

停车辅助功能可能通过系统通知展示停车位置、楼层、车位等信息。

通知是否显示在锁屏，以及锁屏时展示多少内容，由 Android 系统的通知和隐私设置决定。

### 4. 数据备份与导出

应用支持将本地数据导出为 JSON 文件，也支持通过文件导入恢复数据。

**请注意：JSON 备份文件为普通文件，不提供额外的文件加密保护。**

备份文件可能包含车辆信息、加油记录、费用记录和停车信息等个人数据。请妥善保存，不要随意上传到公开网站或分享给他人。

如果将文件保存到第三方网盘或其他云存储位置，其后续存储和处理方式由相应服务提供方决定。

### 5. 第三方服务与外部链接

应用可能在部分功能中调用 Android 系统服务或打开外部网页：

- **地址解析服务（Geocoder）**：应用将 GPS 坐标传递给 Android 系统 Geocoder 接口，尝试转换为文字地址。该接口可能使用网络服务，具体服务提供方、网络请求方式及数据处理方式取决于设备系统和相关服务配置。
- **外部网页**：应用可能通过系统浏览器打开 GitHub、QQ 等外部页面。用户主动打开这些页面后，相关网站和服务可能按照自身的隐私政策处理访问数据。

FuelTracker 不运营自建地址解析服务器，也不会主动将用户的加油记录、费用记录或 JSON 备份文件作为地址解析请求的内容提交给 Geocoder。

需要说明的是，Geocoder 背后的具体服务提供方、服务器位置及其内部数据处理方式不由本应用控制，开发者也无法仅通过 Android 接口确认这些信息。

第三方系统服务和外部网站的数据处理行为，应以其各自的说明或隐私政策为准。

### 6. 数据删除

用户可以通过 Android 系统应用管理功能清除应用数据，或卸载应用，以删除设备上的应用数据。

执行清除或卸载操作前，请先确认是否需要保留已有记录，并及时导出备份。

### 7. 隐私说明的适用范围

本说明主要介绍 FuelTracker 应用自身的数据处理方式。

Android 系统、设备厂商服务、用户主动使用的第三方应用及外部网站可能有各自独立的数据处理规则。

## ⚠️ 使用须知

- 应用中的油耗、费用和停车信息依赖用户输入，建议定期检查记录准确性。
- 导入历史数据前，建议先导出当前数据作为备份。
- 恢复备份可能影响当前已有数据，请确认文件来源和内容后再操作。
- 不同车辆的实际油箱容量、燃油标号和油耗表现可能存在差异，请以车辆实际情况为准。
- 本项目主要用于个人记录与学习交流，不保证所有统计结果与其他油耗软件完全一致。

## 🚀 如何构建

### 环境要求

- Android Studio（支持项目使用的 Android Gradle Plugin）
- JDK 17
- Android SDK：compileSdk 37
- 最低支持版本：Android 11（API 30）

### 构建步骤

1. 使用 Android Studio 打开项目。
2. 等待 Gradle 同步并完成依赖下载。
3. 选择 `app` 运行配置。
4. 点击 Run，安装到设备或模拟器。
